# Curio v0.6.0 账号、词卡与章节插画升级规格

> **状态**：Approved for implementation  
> **日期**：2026-08-11  
> **替代关系**：在 [`spec-p1-completion-and-p2-mvp-v0.5.0.md`](./spec-p1-completion-and-p2-mvp-v0.5.0.md) 基础上增量升级；未冲突的 P1 学习闭环约束继续有效。  
> **范围**：受控试点；不开放公开注册、短信验证码或实时生成插画。

## 1. 目标与边界

本次升级同时解决三个问题：

1. 试点用户以“手机号 + 初始默认密码”登录，并可自行设置、修改密码；
2. 章节词汇卡必须显示真实词库信息和当前章节语境例句，不能再用演示数据或空白区块伪装为完整资料；
3. 关键章节可携带经审核的静态四格漫画，提升叙事吸引力，但不参与词义判断。

本次不承诺：公开注册、找回密码、短信 OTP、给 3,500 个词补造不经审校的词族/例句、或根据答题结果动态生成分支漫画。

## 2. 当前问题与根因（审核事实）

- `vocab_library` 有 3,500 条词，但仅 189 条 `word_family` 非空；这与现有词库构建器的“只收录可明确证明的透明派生词”规则一致，并非 API 漏字段。
- 种子脚本使用 `onConflictDoNothing()`；即使上游 CSV 后续补充字段，已存在的数据库记录也不会刷新。
- 词汇浮层先渲染 `VOCAB_MOCK` 或通用占位，再异步取服务端数据；生产卡片与演示数据混用。浮层也未展示已有的 `example` 字段，并会为 `[]` 词族渲染空标题。
- 第一章历史发布数据把原本不在 3,500 词库的目标词静默替换成 `a`、`a.m.`、`abandon`，造成正文语义断裂；“仅能显示读音”的表象并非单一前端问题，而是词库可用性与章节发布数据未作语义约束共同导致。
- 当前已发布第一章的主线是“深夜快车、父亲信件、车长藏匿包裹”，此前“旧办公室中的信封”四格只适合作为视觉风格样张，不能误挂到第一章正文。

## 3. 手机号与密码

### 3.1 账号开通与登录

- 试点管理员预置手机号；首次迁移为缺少凭据的手机号账号写入默认密码哈希并标记 `must_change_password=1`。
- 默认密码只能由部署环境变量 `PILOT_DEFAULT_PASSWORD` 提供；不得写入代码、数据库明文、日志或前端。生产环境变量长度至少 8，最多 72 字符。
- 用户通过 `POST /api/auth/login`（手机号、密码）登录；旧 `POST /api/auth/pilot/login` 保留为兼容别名。
- 会话仍为 HttpOnly、SameSite=Lax Cookie；连续五次失败锁定 15 分钟的持久化约束继续有效。

### 3.2 设置与修改密码

- `POST /api/auth/password` 仅接受已验证会话，参数为 `currentPassword`、`newPassword`；新密码 8–72 字符，且不得等于当前密码。
- 成功后更新 bcrypt 哈希（cost 10）、`password_updated_at`，清除 `must_change_password`；响应与日志均不含密码或哈希。
- 已登录用户可从首页进入“账户与密码”页修改密码；首次默认密码登录者在首页可见“请修改初始密码”的提示。
- 现有 `pin_hash` 仅作一次兼容读取。成功修改后凭据写入 `password_hash`；不得再新增依赖 `pin_hash` 的代码。

### 3.3 验收

- 默认密码迁移脚本拒绝未配置或不合规的环境变量；不会重置已有 `password_hash` 或 `pin_hash`。
- 预置用户可用手机号和默认密码登录；改密后旧密码失效、新密码可登录。
- 未登录改密、错误当前密码、过短密码、复用当前密码分别返回明确的 401/400/400/400 错误码。

## 4. 词汇卡数据契约

### 4.1 服务端真源

- `/api/learning/vocabulary/:word` 必须返回 `word`、`phonetic`、`pos`、`meaningCn` 和结构化 `wordFamily`；词族成员仅在其自身也存在于 3,500 词库时显示词性与释义。
- 词族为空是合法的“没有可验证的高中范围词族”，前端必须明确显示此状态，不能显示空标题，也不能凭拼写相近自行臆造。
- 词库补数或更正必须使用可重复运行的 upsert，同步更新已有行；`onConflictDoNothing()` 只允许初次导入。

### 4.2 章节语境例句

- 阅读器为每个高亮词从当前章节正文提取含该词的完整句子，作为“本章语境例句”；例句必须来自已发布正文，不另行生成或翻译。
- 词汇浮层首次点击显示加载状态；成功后只渲染服务端数据与本章语境例句。请求失败显示“词卡暂未加载，可重试”，不得回退到 `VOCAB_MOCK` 或泛化的“重点词”文案。
- `VOCAB_MOCK` 仅允许 Onboarding 演示使用，正式阅读器与词汇本不得依赖它。

### 4.3 内容门禁

- 每个发布章节的 15 个目标词必须有音标、词性、中文释义，并能在正文提取一条非空语境例句；功能词与时间缩写（如 `a`、`a.m.`）不得作为章节学习目标。
- 词族覆盖率作为内容质量指标记录，但不把“无可靠词族”判为发布失败；所有非空词族必须去重、不含自身、且成员存在于词库。

## 5. 静态四格章节插画

- 章节可选 `illustration` 元数据：`assetPath`、`alt`、`placement='before_story'`、`panelCount=4`、`assetVersion`。
- 插画只在章节正文前展示；图片不含英文词、释义、正确选项、分支后果或可读文字，不能作为关键抉择的解题依据。
- 仅“已审核、与该章节主线事实一致”的图片可写入发布章节。图片路径必须为项目内静态资源；缺图或无效元数据时正文仍可阅读。
- 第一章必须重新制作与“深夜快车”一致的四格：列车驶出站台 → 林亦读父亲信 → 车长藏匿包裹 → 林亦发现行李舱线索。此前旧办公室样张不进入产品。

### 5.1 验收

- API 快照返回插画元数据；阅读器在正文前显示带 alt 的四格图，移动端不横向溢出。
- 没有插画元数据的章节保持原有正文流程。
- 词汇卡、插画都不改变 15 词预算、关键抉择、支线汇流、辨析任务或完成条件。

## 6. 发布检查

发布前须通过：构建、API 回归测试、词汇与内容门禁、桌面和移动端 E2E。审核记录必须分别列出：已实现能力、未实现边界、数据覆盖率和生产部署前仍需执行的默认密码迁移。
