# 海外前端 + 中国大陆后端：内测期部署与备案评估

> **修订结论（2026-08-03）**：可以做一条技术上可运行的“海外 Pages 前端（`www.daas.ai`）→ 同域 `/api/*` 代理 → 中国大陆腾讯云后端”链路，用于小范围、受邀内测；但它**不能被视为免备案方案**。更重要的是，境外注册商的域名可转入境内有资质的注册服务商后申请 ICP 备案。因此应优先尝试将 **`daas.ai` 本身**转入、完成实名并提交备案；只有在备案控制台确认 `.ai` 后缀不在工信部可备案清单时，才改用新主域名。未备案期间，EdgeOne 仍只能使用“全球可用区（不含中国大陆）”。

## 1. 事实与边界

- 工信部备案规则的适用表述是“在中华人民共和国境内提供非经营性互联网信息服务”；《互联网信息服务管理办法》同时规定非经营性服务实行备案制度。腾讯云面向客户的说明更直接：**所有对中国大陆境内提供服务的网站应先完成 ICP 备案**。因此，“把静态前端放到海外”不是足以得出“对大陆用户无需备案”的合规结论。
  - [工信部：非经营性互联网信息服务备案管理办法](https://wap.miit.gov.cn/zcfg/xxtxl/art/2024/art_7e48434c08c24131b4b7eecfca5b2b6c.html)
  - [工信部：互联网信息服务管理办法](https://www.miit.gov.cn/zwgk/zcwj/flfg/art/2020/art_4c6a91eb93c34a6e8adc5852f9b56fd1.html)
  - [腾讯云：域名注册常见问题](https://cloud.tencent.com/product/domain?d=52up.cn)

- EdgeOne 的正式限制是：加速区域选“中国大陆”或“全球可用区”时需先完成 ICP 备案；未备案域名只能选“全球可用区（不含中国大陆）”。这与当前 `www.daas.ai` 的海外 Pages 状态相符，但也意味着不能使用大陆边缘节点。
  - [腾讯云 EdgeOne：使用限制](https://cloud.tencent.com/document/product/1552/104964)

- EdgeOne Pages / Edge Functions 具备这条链路所需的技术能力：函数在全球边缘节点执行；可用标准 `fetch` 发出远程 HTTP 请求；`/edge-functions/api/[[default]].js` 可接管所有 `/api/*` 路由。站点源站也支持 IP 或域名。因此同域反向代理在产品能力上可实现。
  - [腾讯云 Edge Functions（路由、Fetch、限制）](https://cloud.tencent.com/document/product/1552/127416)
  - [腾讯云 EdgeOne：源站组](https://cloud.tencent.com/document/product/1552/100605)

- 境外注册商的域名不能直接备案，但腾讯云明确允许先转入境内有资质的服务商再申请备案。转入解决的是“注册服务商在境外”这个阻碍；`.ai` 是否最终可备案还要同时满足“后缀已被工信部收录”、域名实名与备案主体一致、域名在有效期等条件。因此应优先对 `daas.ai` 做实际核验，而不是仅根据当前注册地或能否注册来判断。
  - [腾讯云：为什么提示域名后缀不支持备案](https://cloud.tencent.com/document/product/243/19644)
  - [腾讯云：准备 ICP 备案域名](https://cloud.tencent.com/document/product/243/18905)
  - [腾讯云：能否进行备案](https://cloud.tencent.com/document/product/243/19631)
  - [工信部：域名行业管理信息公示 / 中国互联网域名体系](https://domain.miit.gov.cn/chinayu.jsp)

## 2. 可行的短期架构

```text
受邀测试用户（中国大陆）
       │ HTTPS
       ▼
www.daas.ai ── EdgeOne Pages（全球可用区，不含中国大陆）
       │
       ├── 静态页面、资源
       └── /api/* Edge Function（不缓存、鉴权、限流）
                    │ HTTPS + 服务间凭证
                    ▼
           中国大陆腾讯云 API / 后端（数据库仍留在境内）
```

### 为什么选择同域 `/api/*`

浏览器只面对 `https://www.daas.ai`，不额外暴露一个大陆 API 域名，也不需要 CORS。Edge Function 将请求转给后端。该做法只能改善前端接入与域名切换，并**不**让后端成为私网可达：Edge Function 需要能访问一个受保护的 HTTPS 源站。

### Curio 当前代码的适配度

- 前端的默认 API 基址已经是相对路径 `/api`（`apps/web/src/apiClient.ts`），`/api/me` 与 `/api/auth/logout` 也是相对路径。因此上述同域代理不需要把 API 域名编译进前端，也不会引入浏览器跨站 Cookie 问题。
- 试点登录把 `curio_session` 设为 `HttpOnly`、`SameSite=Lax`，且在生产环境开启 `Secure`（`apps/api/src/auth.ts`）。在“`www.daas.ai` + 同域 `/api`”模式下该设置可以沿用；不要改成跨站 Cookie 或把会话令牌交给前端 JavaScript。
- 后端目前的通配 CORS 配置并非同域运行所必需。上线前应改为最小允许来源或移除，并在 Edge Function 处去除客户端伪造的内部鉴权头。
- P1 已使用中国大陆手机号、学习进度和 Cookie 会话，且项目规格已把公开分享、正式手机 OTP、家长访问列为正式发布前需单独隐私评审的事项。这些数据不能因为数据库在大陆就被视为“未出境”。

### 后端最小暴露面

1. 只公开一个 HTTPS API 入口（网关、负载均衡或受控反向代理），应用和数据库继续在大陆 VPC。
2. 后端拒绝直连业务请求：校验服务间签名/JWT、时间戳、防重放；限制来源网络并保留审计日志。不要仅凭可伪造的 `X-Forwarded-For` 头鉴权。
3. `/api/*` 一律绕过 CDN 缓存；Cookie、Authorization、错误响应和用户数据都不得进入共享缓存。限制函数请求体：腾讯云当前 Pages Edge Functions 的 body 上限为 1 MB、单次 CPU 时间为 200 ms。
4. 保留一个仅供运维和故障排查的大陆直连入口，不向测试用户公开；为 Edge Function → 后端的跨境回源设置健康检查、超时和降级页面。

## 3. 不能忽略的风险

| 风险 | 对内测的影响 | 应对门槛 |
|---|---|---|
| 备案 | 海外前端不是备案豁免；若产品实际面向大陆提供服务，不能以此作为长期上线依据。 | 书面向腾讯云备案/合规支持确认该场景，并推进可备案域名。 |
| 体验与可用性 | 未备案域名没有大陆加速，且“海外边缘 → 大陆源站”属于跨境回源，延迟、抖动、丢包及不可用风险均高。 | 只做 5–10 人受邀内测；在三家大陆网络实测 p95、失败率和长连接表现。 |
| 数据出境 | Edge Function 在全球节点处理请求；登录标识、IP、学习记录或日志可能构成向境外提供的个人信息，不能因为数据库留在大陆就忽略。 | 数据流与地区确认、最小化字段、隐私告知与供应商处理条款；由法务按实际节点/日志位置评估。 |
| 安全 | 公开大陆源站会扩大攻击面；代理若透传不当会泄露令牌或缓存个人数据。 | 服务间认证、WAF/限流、回源 allowlist、密钥托管、日志脱敏、渗透/接口测试。 |

腾讯云也明确不保证跨境回源效果，并提供“海外站点的中国大陆网络优化”作为专门能力；这说明跨境链路是可建设但需专项验证的网络问题，而不是无成本替换。

- [腾讯云：跨地域安全加速（海外站点）](https://intl.cloud.tencent.com/zh/document/product/1145/56448)
- [腾讯云：源站配置的跨境回源说明](https://intl.cloud.tencent.com/zh/document/product/228/6289)
- [国家网信办：促进和规范数据跨境流动规定](https://www.cac.gov.cn/2024-03/22/c_1712776612187994.htm)

## 4. 推荐决策：以 `daas.ai` 备案为主、海外链路为临时验证

### 轨道 A：两周内做受控技术内测

前提是项目负责人确认内测仅限受邀、非公开传播，且合规负责人认可风险可控。

1. 在 `www.daas.ai` 配置 `/api/*` Edge Function 代理至大陆受控 API；不开放单独的大陆 API 域名给测试用户。
2. 选择不含敏感个人信息的最小测试集；登录、学习进度等数据只存大陆，边缘仅短暂转发，不持久化用户 payload。
3. 从电信、联通、移动各一条大陆网络实测：首屏 LCP、登录/答题 API p95、错误率、连续 30 分钟稳定性；超过产品设定阈值即停止此方案。
4. 请腾讯云支持书面确认：未备案 `www.daas.ai` 的当前加速区域、边缘函数回源至大陆源站是否有账户/地域/内容限制，以及需要的源站访问控制方式。

**试点放行门槛**：从移动、联通、电信网络各完成一次真实的登录、答题、刷新后会话恢复和登出；后端日志确认请求均经服务间认证、`Set-Cookie` 未丢失、`/api/*` 未命中共享缓存；再以 5--10 名受邀用户进行内测。任何一项不通过，就回退到仅演示静态页面，不把该链路开放给试点用户。

### 轨道 B：优先解除 `daas.ai` 的备案阻碍（正式上线依赖它）

1. 把 `daas.ai` 从境外注册商转入境内有资质的服务商；腾讯云的转入通常需 3--7 个工作日，且不修改 DNS 服务器时不会影响现有解析。
2. 在境内服务商完成域名实名认证，确保域名注册人和备案主体完全一致；实名信息入库后再提交备案（腾讯云建议至少等待三天）。
3. 在腾讯云 ICP 备案控制台和工信部域名行业管理信息公示中，核验 `.ai` 后缀是否可备案。通过即对二级域名 `daas.ai` 办理备案/腾讯云接入备案，届时 `www.daas.ai`、`cu.daas.ai` 等下级域名可使用；不需要逐个子域名单独备案。
4. 备案与腾讯云接入完成后，再将 `www.daas.ai` 的 EdgeOne 服务区域调整为允许中国大陆的配置，并将大陆后端作为受控源站。此时“海外前端 + 国内后端”只是部署选择，不再承担规避备案的角色。
5. **兜底**：仅当第 3 步的真实校验显示 `.ai` 后缀不获支持，才注册可备案的新主域名并按原计划迁移；不要在未做当前域名实测前就放弃 `daas.ai`。

腾讯云文档明确：境外注册商的域名须先转入境内有资质服务商；备案域名需要是国家批复的域名，域名实名信息应与备案主体相符；二级域名备案后可使用相应三级、四级域名。

- [腾讯云：准备 ICP 备案域名](https://cloud.tencent.com/document/product/243/18905)
- [腾讯云：域名转入腾讯云](https://cloud.tencent.com/document/product/242/3645)

## 5. 结论的适用范围

本评估确认的是“技术上能搭出临时链路”，不是法律意见或正式上线批准。最终是否可对中国大陆用户提供服务，应以备案主管部门要求、腾讯云书面答复、实际数据流位置与项目法务审核为准；没有这些证据时，不能将海外 Pages 方案表述为“解决备案”。
