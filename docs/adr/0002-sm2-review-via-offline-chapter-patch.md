# SM-2 复现词通过离线预制章节实现，配额上限5词/章

词汇复现的实现路径分两阶段。

**阶段一（P2 MVP）**：假设所有用户以1章/天的统一节奏推进，SM-2 复现时间表可离线精确推算。对每章 Ch_N，计算哪些历史词汇在第N天到期复现，按优先级取最多 **5个复现词**，通过批量 AI 调用将其以语境词身份自然织入章节基础文本（Level 3 轻度 Patch：插入1-2句），结果写回 `content_library`。所有用户共享同一套预制章节，无实时 AI 调用。

**阶段二（P3）**：根据用户个人 SM-2 状态，AI 完整重写当日章节，实现每用户完全个性化。届时需评估 LLM 调用成本（预估 DAU=1000 时约 ¥50-200/天）和叙事连续性质检方案。

选择离线预制而非实时个性化，是因为阶段一可以验证「复现效果」这一核心假设，同时将工程复杂度控制在 P2 范围内。5词/章的配额是在「遗忘曲线覆盖速度」和「叙事阅读密度」之间取得平衡的折中点——超出配额的词汇顺延至下一个复现窗口，允许比 SM-2 理论时间晚1-2章。

## Consequences

- 当前 `content_library` 的10章需要重新用 AI 批量生成（加入复现词）
- `generate-stories.ts` 脚本需改造：增加复现词计算逻辑和轻度 Patch 调用
- 阶段一下，用户学习进度快慢不影响复现时机（所有人看同一章），这在阶段二才能修正
