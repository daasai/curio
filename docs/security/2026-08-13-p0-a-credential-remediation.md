## 已确认风险

1. `scripts/complete-chapters.ts` 曾把一个火山引擎方舟 LLM 凭证作为环境变量缺失时的源码回退。本文不记录凭证值。
2. API 会话签名曾在非生产环境回退到源码内固定值。虽然生产启动校验会拒绝该值，但开发或误配置运行仍可能使用可预测签名。
3. `deploy.sh` 曾在部署目标缺少 `.env` 时复制 `.env.example`，可能把空安全变量带入后续流程；校验发生在依赖安装和数据库迁移之后。
4. `.gitignore` 未覆盖所有 `.env.*` 和 SQLite 主数据库文件。
5. 仓库没有受控同步脚本，人工同步是否排除服务器 `.env` 与 `data/` 依赖操作纪律。

## 已交付改造

- 删除 LLM 真实凭证回退，只接受 `LLM_API_KEY` 的环境变量或密钥管理注入；缺失时在访问数据库或网络前失败。
- LLM 请求失败不再把供应商响应正文写入日志，重试日志只保留不含请求头的错误摘要。
- 删除 API 固定 JWT 回退；服务启动要求 `JWT_SECRET` 至少 32 字节，生产环境继续拒绝不安全 Cookie 配置。
- API 与浏览器测试使用运行时随机生成的签名密钥，不把固定测试密钥升级为新的回退。
- 部署脚本不再创建或覆盖 `.env`，且在安装依赖、迁移数据库前检查 `.env`、文件权限、安全变量与现有 `data/curio.db`。
- 新增默认仅预览的 `scripts/sync-deploy.sh`；显式排除 `.env`、所有 `.env.*`、`data/`，且不使用远端删除参数。
- 扩充 `.gitignore`，保留 `.env.example`，忽略真实环境文件和 SQLite 主文件、WAL、SHM。
- 新增 `test:credential-safety` 静态门禁，并接入 `quality:check`。门禁覆盖源码、配置模板、部署脚本、文档和 `apps/web/dist`，只输出文件、行号和风险类型。
- 本地 `.env` 权限已收紧为仅当前用户可读写；未读取、复制或记录其值。
