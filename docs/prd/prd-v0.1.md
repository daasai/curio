## 一、产品概述

### 1.1 产品定位

**Curio** 是一款面向高中生的 AI 英语词汇沉浸式学习产品。

> 借助 AI 动态生成能力，将枯燥的背单词任务转化为个性化的沉浸式故事体验——单词不是要背的清单，而是推动剧情发展的关键。

### 1.2 核心理念

```
传统产品解决的问题：如何让学生坚持刷单词
Curio 解决的问题：如何让单词在有意义的语境中真正活起来
```

### 1.3 Slogan

> **每个单词，都是一个世界的入口**

### 1.4 产品名称释义

**Curio**（奇珍异品）= Curiosity（好奇心）的缩写核心，寓意：  
用好奇心驱动学习，让每一个词汇都成为值得探索的奇妙世界。

## 二、问题与机会

### 2.1 现状诊断

高中英语词汇学习是一个**持续存在的刚需痛点**：

- 高考英语词汇量要求约 **3500 个**（新课标 II 级）
- 高中生平均词汇留存率仅约 **30%**（艾宾浩斯遗忘曲线影响）
- 市面上主流产品（扇贝、百词斩、不背单词等）的核心交互模式在过去10年几乎没有本质改变

### 2.2 三层问题拆解

| 层次 | 真正的问题 | 传统产品的应对 | 根本缺陷 |
|------|-----------|--------------|---------|
| **认知层** | 单词是孤立符号，缺乏意义网络 | 提供例句、词根词缀 | 仍是被动消费，不产生连接 |
| **情绪层** | 重复 = 无聊，大脑主动抵抗记忆 | 贴卡通皮、加音效、积分 | 表面趣味化，底层仍是题海 |
| **动机层** | 看不到"真实使用英语"的场景 | 排行榜、连续打卡激励 | 外部激励短效，停用率高 |

### 2.3 AI 带来的结构性机会

传统产品受限于**静态内容库**，只能靠 UX 技巧堆砌趣味感。  
**生成式 AI 的核心能力是动态生成**——这才是真正改变游戏规则的地方：

| 传统产品能做的 | AI 让我们能做的 |
|--------------|----------------|
| 固定例句展示 | 实时生成个性化语境故事 |
| 预设题目库 | 动态生成与剧情绑定的测验 |
| 通用学习路径 | 基于遗忘曲线的个性化词汇调度 |
| 一次性内容消费 | 持续演化的故事世界 |

## 三、目标用户

### 3.1 MVP 阶段聚焦

| 维度 | 定义 |
|------|------|
| **学段** | 高中生（高一 ~ 高三） |
| **学科** | 英语词汇（高考词汇表范围） |
| **使用动机** | 主动自驱学习（非家长/老师强制驱动） |
| **使用场景** | 独自学习，不依赖社交/竞争激励 |
| **平台** | Web 端（MVP 阶段） |

### 3.2 核心用户画像

#### 画像 A：「焦虑型自驱者」小林（高二，16岁）

- **痛点**：高考压力大，明知要背单词，但每次打开刷词 App 10 分钟就失去兴趣
- **行为特征**：喜欢看悬疑小说/剧集，习惯睡前刷手机30分钟
- **对产品的期待**：背单词的时候能像追剧一样停不下来
- **使用 Curio 的场景**：睡前 15 分钟，独自沉浸阅读

#### 画像 B：「效率型目标导向者」陈同学（高三，17岁）

- **痛点**：词汇量够但阅读理解失分，单词在语境中认不出来
- **行为特征**：学习计划性强，关注英语成绩提升
- **对产品的期待**：词汇真正在语境中被掌握，不只是认识孤立的词
- **使用 Curio 的场景**：每天早读前10分钟，完成今日词汇故事

## 四、产品策略

### 4.1 核心设计原则

1. **效果第一**：学习效果是目标，沉浸感是手段，两者通过故事协同实现
2. **意义驱动**：词汇学习必须发生在有意义的语境中，绝不孤立记忆
3. **无感科学**：遗忘曲线等记忆科学在后台静默运行，用户毫无感知
4. **零挫败感**：没有"答错了"，只有"故事走向了不同方向"
5. **真实个性化**：基于兴趣的内容生成，而非表面的皮肤/主题切换

### 4.2 差异化定位矩阵

```
                    趣味性高
                      ↑
         Curio ★      │      多邻国
    （深度沉浸式）    │  （轻量碎片化）
                      │
  ←─────────────────────────────────→
   学习效果弱        │        学习效果强
                      │
    百词斩            │      扇贝/不背单词
  （娱乐化皮肤）    │    （系统化刷题）
                      ↓
                    趣味性低
```

### 4.3 核心壁垒

1. **个性化故事数据**：用户的兴趣偏好、阅读行为、词汇掌握数据，构成难以复制的个性化模型
2. **故事-词汇绑定机制**：将学习行为深度嵌入叙事体验，竞品难以在不重建核心体验的前提下模仿
3. **词汇语境记忆网络**：用户在 Curio 中建立的"词汇→故事场景"记忆网络，形成平台黏性

## 五、核心体验设计

### 5.1 核心学习循环

```
┌─────────────────────────────────────────────────────────────┐
│                     CURIO 核心学习循环                        │
│                                                              │
│  ① 兴趣校准                                                  │
│     └─ 用户选择故事类型偏好（首次 + 持续更新）               │
│          ↓                                                   │
│  ② 今日故事生成                                              │
│     └─ AI 基于兴趣偏好 + 今日词汇集 生成专属叙事             │
│          ↓                                                   │
│  ③ 沉浸阅读                                                  │
│     └─ 词汇首次出现仅做轻量高亮，不打断阅读流                │
│          ↓                                                   │
│  ④ 关键抉择                                                  │
│     └─ 剧情节点出现多选题，测验词义理解                      │
│          ↓                                                   │
│  ⑤ 自然复现                                                  │
│     └─ 词汇在后续章节以不同语境反复出现（遗忘曲线驱动）     │
│          ↓                                                   │
│  → 下一个 Session                                            │
└─────────────────────────────────────────────────────────────┘
```

### 5.2 故事结构：双轨制

#### 主线连载（Main Arc）

| 维度 | 说明 |
|------|------|
| **形式** | 持续演化的长篇故事，每天更新一章 |
| **长度** | 约 600~1000 字/章（对应8~15分钟阅读） |
| **连续性** | 人物、世界观、前情保持一致 |
| **词汇密度** | 每章嵌入 3~8 个目标词汇 |
| **剧情驱动力** | 每章末尾留有悬念，驱动次日回访 |
| **可选故事类型** | 悬疑推理 / 科幻冒险 / 校园青春 / 历史架空 / 体育竞技 |

#### 每日短篇（Daily Flash）

| 维度 | 说明 |
|------|------|
| **形式** | 独立完整的短故事，单次可读完 |
| **长度** | 约 300~500 字（对应5分钟阅读） |
| **连续性** | 无需前情，适合碎片化使用 |
| **词汇密度** | 每篇嵌入 2~4 个目标词汇 |
| **功能定位** | 主线补充 / 时间不足时的备选 / 特定词汇强化练习 |

### 5.3 关键抉择机制（Key Choice）

> 这是 Curio 区别于所有现有产品的**核心差异化机制**。

#### 设计原理

传统词汇测验：
```
展示单词 → 选择正确释义 → 对/错反馈
```

Curio 关键抉择：
```
推进剧情 → 面临抉择 → 做出选择 → 故事继续演化
```

关键差异：**用户在乎的是故事走向，不是答对答错**。

#### 交互流程

```
① 叙事铺垫
   │  故事推进到关键节点，情节描述中自然嵌入目标词汇
   │  学生已通过阅读对词汇有初步语境感知
   ↓
② 抉择呈现
   │  出现带有代入感的选择题（非"这个词的意思是……"的传统形式）
   │  选项直接与剧情后续走向绑定
   ↓
③A 选择正确
   │  故事正向推进，解锁更精彩情节
   │  短暂正向反馈（「推理正确！」）
   │  继续阅读
   ↓
③B 选择错误
   │  故事走向支线，AI 在支线叙事中自然呈现词义
   │  无负面情绪标签，仅提示「这条路走向了另一个方向……」
   │  支线结束后给予第二次机会
```

#### 抉择示例（以词汇 "ambiguous" 为例）

> **场景**：侦探在案发现场发现一封信，信中措辞极为 *ambiguous*，每一句话都像同时指向两个方向。

> **抉择**：根据这封信的特点，Elena 应该……

- A. 立即锁定嫌疑人，信已经指向了明确目标
- **B. 继续收集证据，信的内容含混不清，无法得出可靠结论** ✓
- C. 忽略这封信，它只是烟雾弹
- D. 将信件公开，让所有人帮助分析

> **正确反馈**：`推理正确！Elena 明白，真正的 ambiguous 意味着证据本身具有歧义性——在这种情况下，任何仓促的结论都可能是致命的错误。`

### 5.4 词汇三阶段曝光模型

```
第一阶段：【无感嵌入】
   词汇在叙事文本中自然出现
   仅做轻量视觉标记（淡金色高亮）
   点击可查看词义，但不强制
   目标：产生「这个词是什么意思？」的自发好奇心

           ↓  （当次或下一次阅读）

第二阶段：【主动验证】
   通过「关键抉择」验证词义理解
   在做选择的过程中强化记忆编码
   目标：建立词义→故事情境的深度关联

           ↓  （间隔重复，遗忘曲线驱动）

第三阶段：【自然复现】
   词汇在后续故事中以不同语境再次出现
   学生感知到的是「这个词又出现了，我认识它！」
   目标：多维度语境构建，从认知到真正掌握
```

### 5.5 用户完整旅程

#### 首次使用（Day 1）

```
打开 App
  → 欢迎页（产品价值传达，30秒内）
  → Onboarding Step 1：选择故事偏好（3~6个类型，可多选）
  → Onboarding Step 2：设置学习参数（时长、词汇量滑块）
  → Onboarding Step 3：确认设置预览，生成第一个故事
  → 首页 Dashboard
  → 进入第一章主线故事
  → 完成第一个关键抉择
  → 当天学习完成，词汇入库
```

#### 日常使用（Day 2+）

```
打开 App（通知唤醒 or 主动进入）
  → 首页 Dashboard（看到今日状态：连续天数、今日词汇预览）
  → 选择：继续主线 or 今日短篇
  → 沉浸阅读 + 关键抉择
  → 完成反馈 + 词汇入库
  → （可选）查看词汇本，回顾语境
```

#### P0（MVP 必须）

| 功能模块 | 功能点 | 说明 |

| **关键抉择** | 抉择题展示 | 带情境的多选题，与剧情紧密结合 |
| **关键抉择** | 正确/支线反馈 | 正确则继续正线，错误则进入支线叙事 |

| **词汇本** | 已学词汇列表 | 展示本周/全部已接触词汇 |
| **词汇本** | 词汇语境回顾 | 每个词汇显示其在故事中的原句 |

#### P1（原型验证后迭代）

| 功能模块 | 功能点 | 说明 |
|---------|-------|------|
| **学习报告** | 每周词汇掌握简报 | 本周新词、掌握率、阅读时长 |
| **设置** | 偏好调整 | 故事类型、时长、词汇量重新设置 |
| **通知** | 每日学习提醒 | 浏览器通知，时间可配置 |
| **进度可视化** | 词汇掌握度曲线 | 展示词汇在遗忘曲线中的位置 |

#### P2（功能 MVP 阶段）

| 功能模块 | 功能点 | 说明 |
|---------|-------|------|
| **AI 真实接入** | 实时故事生成 | 接入 LLM API，替换 Mock 数据 |
| **用户账号** | 注册/登录/数据同步 | 跨设备数据持久化 |
| **词汇系统** | 完整高考词汇库 | 3500 词分级管理 |
| **遗忘曲线引擎** | 真实词汇调度算法 | 基于用户答题历史自动调度 |

#### 明确不做（MVP 阶段）

| 功能 | 不做的原因 |
|------|----------|
| 社交功能/排行榜 | 用户偏好独自沉浸；增加产品复杂度 |
| 口语/发音练习 | 超出 MVP 核心场景 |
| 家长端/老师端 | 后续商业化阶段考虑 |
| 移动端 App | Web 验证核心体验后再做 |
| 语法学习 | 聚焦词汇场景，避免分散 |

| 词汇高亮 | 金色底色 + 下划线；点击弹出词义卡片（不遮挡正文） |
| 提示文案 | 「💡 点击金色高亮单词，查看词义提示」 |
| 关键抉择区 | 分割线隔开；⚡ 图标 + 「关键抉择」标签；情境描述 + 选择题 |
| 选项卡片 | 字母标签 + 选项文字；hover 时左边出现金色竖条 |
| 反馈区域 | 正确：绿色 Glass Card + 文字反馈 + 「继续故事」按钮；错误：红色 Glass Card + 词义说明 |

## 七、AI 系统设计

### 7.1 AI 能力需求

| 能力 | 详细说明 | 难度评估 |
|------|---------|---------|
| **故事生成** | 根据「故事类型 + 目标词汇列表 + 前情摘要」生成新章节 | 中 |
| **词汇无痕嵌入** | 将指定词汇自然融入叙事，避免生硬插入 | 中高 |
| **关键抉择生成** | 自动生成与词义紧密关联的剧情选择题 + 支线叙事 | 高 |
| **故事连续性维护** | 跨章节保持人物、世界观、情节的一致性 | 高 |
| **词汇调度** | 基于遗忘曲线和答题历史，决定今日词汇集合 | 中（算法） |

### 7.2 Prompt 策略（概要）

**故事生成 Prompt 核心要素：**

```
角色设定：你是一名专业的短篇故事创作者，擅长为高中生创作
         有代入感的【故事类型】题材故事

约束条件：
- 本章需要自然地嵌入以下词汇：[词汇列表]
- 词汇必须在叙事中显得自然，不能生硬
- 前情摘要：[上一章内容摘要]
- 本章需在结尾留有悬念
- 字数约 700 字

输出格式：
- 正文（纯叙事）
- 词汇位置标注（用于前端高亮）
- 本章摘要（用于下一章的 Prompt 前情）
- 关键抉择题目 + 正确选项 + 3个干扰项 + 支线叙事
```

### 7.3 词汇调度算法（MVP 简化版）

MVP 阶段使用简化的遗忘曲线模型：

```
词汇状态分类：
  - 未接触：首次出现
  - 已接触：在故事中出现过，未做抉择
  - 已测验：完成了关键抉择
    - 答对：计入"已掌握"，按遗忘曲线安排复现
    - 答错：优先在下一个 Session 的故事中复现

复现间隔（简化 SM-2 算法）：
  第一次答对 → 1天后复现
  第二次答对 → 3天后复现
  第三次答对 → 7天后复现
  第四次答对 → 21天后复现
```

## 十、风险与应对

| 风险 | 可能性 | 影响 | 应对策略 |
|------|--------|------|---------|
| **AI 生成故事质量不稳定** | 高 | 高 | 建立人工质检 + 故事模板约束层；初期人工辅助生成 |
| **词汇嵌入生硬，破坏沉浸感** | 中 | 高 | 精调 Prompt；设置人工审核阈值；用户反馈机制 |
| **学生觉得「太轻松」，担心无效** | 中 | 中 | 在词汇本中展示科学记忆进度；设计学习报告让效果可见 |
| **故事类型偏好与词汇不兼容** | 中 | 中 | 建立故事类型 × 词汇难度的映射规则；设置降级方案 |
| **高中生时间有限，使用场景窄** | 低 | 中 | 确保每日短篇 5 分钟内可完成；支持断点续读 |
| **LLM API 成本过高** | 中 | 中 | 选择性缓存 + 批量生成；商业化后再做规模化 |
